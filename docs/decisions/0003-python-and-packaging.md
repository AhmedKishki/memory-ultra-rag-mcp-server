# ADR 0003: Python and Packaging Contract

Status: accepted

Date: 2026-09-18

## Decision

The package supports CPython 3.11 and 3.12. Its package metadata must declare:

```toml
requires-python = ">=3.11,<3.13"
```

CPython 3.12 is the default development interpreter, but every release gate
must run on both supported minor versions. PyPy and CPython 3.10, 3.13, and
later are unsupported until the complete test and dependency matrix passes on
them. This interpreter decision does not itself declare an operating-system
support matrix; that matrix is finalized with the SQLite FTS5 check.

The project will be an installable Python distribution with:

- distribution name `memory-ultra-rag-mcp`;
- import package `memory_ultra_rag_mcp` under `src/`;
- console command `memory-ultra-rag-mcp` calling
  `memory_ultra_rag_mcp.server:main`;
- static PEP 621 metadata in `pyproject.toml`;
- `setuptools==84.0.0` with `setuptools.build_meta` as the build backend; and
- `[tool.uv] package = true` so the local package is installed into its managed
  environment.

The build backend is deliberately small and matches the audited UltraRAG
package boundary. Dynamic versioning, plugin-based version discovery, a second
package manager, and a native build tool are not needed.

## `uv` workflow

`uv` is the only environment, dependency, locking, and build frontend for this
repository. Milestone 1 must add:

- a `.python-version` selecting `3.12` for local development;
- `pyproject.toml` containing the exact direct pins from ADR 0002;
- `[tool.uv] required-version = ">=0.12,<0.13"`;
- a generated, committed cross-platform `uv.lock`; and
- `.venv/` in `.gitignore`.

The canonical commands will be:

```bash
uv sync --frozen
uv run --frozen pytest
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv build
```

`uv.lock` is generated by `uv` and must not be edited manually. Normal installs
and CI consume it with `--frozen`; deliberate dependency changes update it and
follow the review process in ADR 0002. The project uses one repository-local
`.venv` for development. Research projects served by the installed MCP do not
receive or require their own virtual environments.

No static type-checker dependency is added for the first package slice. Public
and internal functions still require type annotations, with schema validation
and behavior covered by tests. A checker may be added later only with a defined
command and demonstrated value.

## Evidence

- The audited UltraRAG snapshot declares CPython `>=3.11,<3.13`; matching that
  range avoids a second interpreter contract when the deferred retriever is
  evaluated.
- The exact runtime dependencies from ADR 0002 resolved and imported together,
  and the development tools resolved in the same environments, on CPython
  3.11.15 and 3.12.3 on Linux x86-64.
- `setuptools==84.0.0` imported successfully on both versions.
- `uv 0.12.0` performed both isolated resolutions. The accepted range permits
  compatible 0.12 patch releases without silently crossing into a new minor
  tool contract.
- The `uv` documentation defines a build system as the trigger for installing a
  project package, recommends a committed lockfile, and documents frozen syncs:
  [project configuration](https://docs.astral.sh/uv/concepts/projects/config/)
  and [locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/).

## Deferred scaffolding

This ADR chooses the contract but does not create an empty package. Milestone 1
creates `pyproject.toml`, `uv.lock`, the `src/` package, tests, and the real
stdio entry point together so the first scaffold is executable rather than a
placeholder.

The first package gate must verify a frozen sync, source and wheel builds,
installation of the built wheel, console-script startup, and tests on both
supported Python versions.
